# Tiemora Core v0.2.0 — result

Companion to [v0.2-plan.md](v0.2-plan.md). Written after implementation, on the `v0.2-sale-orders`
branch, against `flower-demo` as reference only (never merged).

## 1. Taken into Core

- Catalog: `type` (rental / sale), `price.sale`, product `options`/`addons`, `fulfillment`,
  `ordering` metadata, `category` as a list — `core/catalog/collect.mjs`.
- Orders domain: `core/orders/rules.mjs` (new), `core/notifications/orders.mjs` (new),
  `core/notifications/messages.mjs` (`contactDetails` split out).
- Store configuration: `ordering:` section, `logoStyle`, `hero.eyebrow/subtitle/fit/focus`,
  `store.text` — `core/config/store.mjs`.
- Worker: `worker/orders.mjs`, `worker/orders-db.mjs`, `worker/customer.mjs` (new); `worker/api.mjs`
  (order routes, dashboard/alerts merge, `ADMIN_READ_ONLY` guard); `worker/push.mjs` (order payload).
- Storefront: `storefront/order.js` (new, generic copy — see §2), `catalog.js`, `app.js`,
  `styles.css` (theme-derived hover/selected states, no store-specific literal colours),
  `privacy.html`, `index.html`.
- Admin: Orders list / detail / status flow / schedule / staff-entered orders / notification
  helper, module detection from the catalog, read-only banner — `admin/admin.js`, `admin/index.html`,
  `admin/admin.css`, `admin/manifest.webmanifest`.
- Build/lint: `scripts/build.mjs` (+`order.js`), `eslint.config.mjs` (+globals).
- Migration: `migrations/0006_orders.sql` (additive; `orders`, `order_items`).
- Examples: `examples/sale/` (3 generic sale products), `seed/sale-demo.sql`.
- Docs: `docs/orders.md` (new); `docs/catalog.md`, `docs/configuration.md`, `docs/architecture.md`
  updated; `README.md`, `CHANGELOG.md` updated; `package.json` version.

## 2. Excluded as Flower-Demo-specific (left out of Core)

- Hana Hiên name, tagline, hero copy, logo/hero images, `store.text` overrides written for a florist.
- The 8 flower products, their photos, categories (`20-10`, `for-mom`, …), option/add-on catalog and
  message-card templates tuned for the 20/10 campaign, `config/store.yaml`'s campaign dates.
- `seed/demo.sql`'s florist order data; `wrangler.jsonc`'s `flower-demo` worker name / database id;
  `package.json`'s `hanahien-web` name.
- The order confirmation greeting's flower emoji (🌸) — removed from Core's default templates so the
  wording stays industry-neutral (`core/notifications/orders.mjs`).
- `storefront/order.js`'s default copy that assumed flowers/bouquets ("Đặt hoa", "/ bó", the
  Women's-Day card placeholder) — reworded to industry-neutral defaults ("Đặt hàng", "/ item", a
  generic "write your message" placeholder) before porting to Core.

## 3. Sent to Tiemora Studio candidates

Store setup form, theme/logo/hero picker, campaign screen, product form with image upload/crop,
ordering config editor, copy presets per industry, one-click Cloudflare provisioning, sample-data
generator — none implemented in Core; see `docs/releases/v0.2-plan.md` §C.

## 4. Deferred to Pho / Cafe / Workshop demos

Unified `orders`/`reservations` model, `capacity_overrides` table, staff/resource and workshop seat
models, a single `/api/availability?type=` endpoint, `preset:` industry config, a shared notification
template engine, an explicit `admin.modules` registry, `dine_in`/`on_site`/`rental_handover`
fulfillment — see `docs/releases/v0.2-plan.md` §D. None of these were implemented.

## 5. DB migration

`migrations/0006_orders.sql` (additive): new `orders` and `order_items` tables and indexes only;
`migrations/0001`–`0005` are untouched. Verified: a fresh database applies all 6 migrations in order
(`tests/core/migrations.test.mjs`); an existing v0.1.0 database upgrades in place by design (additive
migration, applied on top of `0001`–`0005` which are unchanged).

## 6. API

New: `GET /api/orders/config`, `POST /api/orders`, `GET/POST /api/admin/orders`,
`GET /api/admin/orders/schedule`, `GET/PATCH/DELETE /api/admin/orders/:id`,
`POST /api/admin/orders/:id/status`, `POST /api/admin/orders/:id/notification`. Existing rental
endpoints (`/api/reservation-requests`, `/api/admin/reservations*`, `/api/availability`, push,
auth) are unchanged. `GET /api/admin/session` gained `readOnly`; `GET /api/admin/dashboard` and
`GET /api/admin/notifications` now merge order alerts alongside rental ones.

## 7. Config

`config/store.yaml`: added `store.logoStyle`, `store.hero.eyebrow/subtitle/fit/focus`, `store.text`
(empty by default), a generic `ordering:` section (fulfillment, dates, time slots, `options.size`,
`addons.giftwrap`, message card) and two new category labels (`gifts`, `seasonal`) used by
`examples/sale/`. Rental keys (`booking.*`, `categories.rental/accessories`, `catalog.dir`) are
unchanged; `catalog.dir` still defaults to `examples/catalog` (rental).

## 8. Admin

Orders module added, shown only when the catalog contains `type: sale` products (module detection,
not a new registry). Read-only banner and `ADMIN_READ_ONLY` guard added for public demos.

## 9. Tests

New: `tests/core/orders.test.mjs`, `tests/worker/orders.test.mjs`, `tests/ui/orders.test.mjs`,
plus a sale-catalog case in `tests/core/catalog.test.mjs` and a sale-seed case in
`tests/core/seed.test.mjs`. Updated for the new tables/DOM: `tests/core/migrations.test.mjs`,
`tests/ui/frontend.test.mjs`. All test fixtures use generic identifiers (`sale-1`, `sample-item-1`,
"Sample Store", …), not Hana Hiên data. `npm test`: **106/106 pass**.

## 10. v0.1 compatibility

Every pre-existing v0.1.0 test file passes unmodified except the two updated for the new schema/DOM
noted above (both additive assertions, no v0.1 behaviour changed). Rental catalog, availability,
reservation requests, physical inventory, admin booking, Web Push and customer notifications are
untouched in source.

## 11. Secret scan

Searched the full working tree for Hana Hiên contact/address/product data and images, 20/10
campaign-specific data, real customer data, real phone numbers, Cloudflare database/account ids,
Worker secrets, `ADMIN_PASSWORD`, Turnstile secret, VAPID private key. None found outside historical
references in `docs/flower-demo/` (kept as the Flower Demo's own record) and `docs/releases/v0.2-plan.md`
(which documents what was deliberately excluded). `wrangler.jsonc` keeps the v0.1 placeholder
`database_id` and worker/database name `tiemora`; `package.json` keeps the name `tiemora`.

## 12. `npm run check`

Lint, typecheck, 106 tests and build all pass on `v0.2-sale-orders`.

## 13. Release readiness

v0.2.0 is ready to release as "Tiemora Core v0.2.0: Sale / Pre-order / Orders", additive on top of
v0.1.0, with `flower-demo` remaining a separate reference-implementation branch that is not merged.
