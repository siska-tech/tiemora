# v0.3.0 merge notes

This branch promotes the generic local-store capabilities identified in the
[Phở feedback](../pho-demo/core-feedback.md). The implementations are already present;
the release consolidates their public documentation and package version.

## Included

| Capability | Contract |
|---|---|
| Dine-in and table metadata | `fulfillment.dine_in` defaults off; `ordering.tables` validates a canonical table number. Tables do not reserve seats. Contact details are optional for dine-in. |
| Opening hours | Weekday intervals constrain service dates and scheduled slots in the store timezone; empty configuration is unrestricted. |
| ASAP | Opt-in, today only, no time slot; checked against opening hours and daily capacity. `leadMinutes` is informational. |
| Daily stock | Product `ordering.stockPeriod: daily` scopes stock to `fulfillment_date`; omitted means `total`. |
| Order Queue and Menu | Staff advance active orders and switch sale products off. Clearing a switch cannot override exhausted stock. |
| Multi-item API | `items[]` is priced from the catalog on the server. Each order has one fulfillment type, date and timing choice. Legacy single-item requests still work. |
| Storefront configuration | QR fulfillment/table hints, copy overrides for page/catalog/form, message-card title and environmental hero layout. |

The cart UI and persistence implementation ship in this branch. This does **not** freeze
`tiemora-cart-v1` or its subscribe/snapshot interface as a stable extension API. The Café
demo will validate food and merchandise together before that decision. Mixed fulfillment,
order/booking combined checkout, seat reservations, menu scheduling and QR sheet generation
remain deferred.

Demo menu data, art, wording, hours and capacities live in `examples/pho-demo/`.
Core defaults to the generic rental sample in `config/store.yaml`. Run `npm run build:pho-demo`
to select the food demo without editing the standard configuration. Its hero and logo are
overlaid from `examples/pho-demo/assets/` only for that build.

## Upgrade from v0.2.0

1. Back up the deployment database and retain the store's own config, catalog and Wrangler settings.
2. Apply all pending migrations before deploying: `npm run db:migrate` (remote), or
   `npm run db:migrate:local` for local development. These add `0007` (dine-in/table),
   `0008` (staff availability) and `0009` (ASAP).
3. Build and deploy using the existing deployment configuration. New ordering modes
   require explicit configuration; existing pickup/delivery and rental settings keep their defaults.
4. Check an existing order and its lines, a new order, admin status transitions and the
   sold-out switch. If enabled, check table validation and ASAP acceptance during opening hours.

`0007` preserves orders and lines from the **released v0.2 schema**. An experimental
database with an edited `0006` needs separate review: `0007` initializes table numbers
to an empty string and does not preserve pre-existing experimental table values.
See the [demo deployment notes](../pho-demo/deployment.md).
